Pipeline Overview

Architecture and strategy for ShopWave CI/CD

What This Pipeline Covers

ShopWave is a multi-service platform with 9 deployable units. This pipeline automates the full lifecycle:


Service Type Deploy Target Trigger
Backend FastAPI Railway Push to main + backend/**
Frontend React SPA Vercel Push to main + frontend/**
mcp-inventory MCP Server Railway Push to main + mcp-servers/inventory/**
mcp-payments MCP Server Railway Push to main + mcp-servers/payments/**
mcp-search MCP Server Railway Push to main + mcp-servers/search/**
mcp-notifications MCP Server Railway Push to main + mcp-servers/notifications/**
mcp-analytics MCP Server Railway Push to main + mcp-servers/analytics/**
mcp-content MCP Server Railway Push to main + mcp-servers/content/**
Database PostgreSQL 18 Neon (Managed) Migrations via backend deploy
💡
Path-based triggers ensure that only affected services are rebuilt and redeployed when code changes. A change to frontend/ will not trigger backend CI.

Pipeline Flow

From commit to production in under 5 minutes

High-Level CI/CD Stages

📝
Commit
Push to branch or open PR
🔍
Lint & Check
Ruff, ESLint, Pyright type checks
🧪
Test
Pytest + Vitest with coverage
🏗️
Build
Docker images + Vite bundle
🚀
Deploy
Railway + Vercel + Neon migrations
✅
Verify
Health checks + smoke tests
1

PR Workflow (CI)

  • Triggered on pull requests to main
  • Runs lint, type-check, and tests in parallel
  • Builds Docker images to validate Dockerfiles
  • Posts check status back to the PR
  • Blocks merge if any step fails
2

Main Branch Workflow (CD)

  • Triggered on merge/push to main
  • Runs full CI suite first ↑
  • Deploys affected services only
  • Runs Alembic migrations on Neon
  • Executes post-deploy health checks

Backend CI Workflow

.github/workflows/backend-ci.yml
📄 .github/workflows/backend-ci.yml 
# ──────────────────────────────────────────────────────────────
# ShopWave Backend CI — FastAPI + PostgreSQL
# ──────────────────────────────────────────────────────────────

name: Backend CI

on:
  push:
    branches: [main]
    paths:
      - 'backend/**'
      - '.github/workflows/backend-ci.yml'
  pull_request:
    branches: [main]
    paths:
      - 'backend/**'

env:
  PYTHON_VERSION: "3.12"
  DATABASE_URL: postgresql+asyncpg://test:test@localhost:5432/test_db

jobs:
  lint-and-typecheck:
    name: 🔍 Lint & Type Check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}

      - name: Install dependencies
        run: |
          cd backend
          pip install -e ".[dev]"

      - name: Ruff lint
        run: cd backend && ruff check .

      - name: Ruff format check
        run: cd backend && ruff format --check .

      - name: Pyright type check
        run: cd backend && pyright

  test:
    name: 🧪 Tests
    runs-on: ubuntu-latest
    needs: lint-and-typecheck

    services:
      postgres:
        image: postgres:18-alpine
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test_db
        ports: ["5432:5432"]
        options: --health-cmd "pg_isready" --health-interval 10s --health-timeout 5s --health-retries 5

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}
          cache: "pip"

      - name: Install dependencies
        run: |
          cd backend
          pip install -e ".[dev]"

      - name: Run migrations
        run: cd backend && alembic upgrade head
        env:
          SECRET_KEY: test-secret-key-for-ci

      - name: Run tests with coverage
        run: |
          cd backend
          pytest --cov=app --cov-report=xml --cov-report=term-missing -v
        env:
          SECRET_KEY: test-secret-key-for-ci
          MCP_INTERNAL_API_KEY: test-mcp-key

      - name: Upload coverage
        if: always()
        uses: codecov/codecov-action@v4
        with:
          file: backend/coverage.xml
          flags: backend

  docker-build:
    name: 🏗️ Docker Build
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: |
          docker build -t shopwave-backend:ci \
            --target runtime \
            ./backend
✅
PostgreSQL Service Container: GitHub Actions spins up a real PostgreSQL 18 instance for integration tests — same version as production.

Frontend CI Workflow

.github/workflows/frontend-ci.yml
📄 .github/workflows/frontend-ci.yml 
# ──────────────────────────────────────────────────────────────
# ShopWave Frontend CI — React 19 + Vite 6
# ──────────────────────────────────────────────────────────────

name: Frontend CI

on:
  push:
    branches: [main]
    paths: ['frontend/**']
  pull_request:
    branches: [main]
    paths: ['frontend/**']

jobs:
  lint-and-test:
    name: 🔍 Lint & Test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: "npm"
          cache-dependency-path: frontend/package-lock.json

      - name: Install dependencies
        run: cd frontend && npm ci

      - name: ESLint check
        run: cd frontend && npx eslint src/ --max-warnings 0

      - name: Run unit tests
        run: cd frontend && npx vitest run --coverage

      - name: Upload coverage
        uses: codecov/codecov-action@v4
        with:
          flags: frontend

  build:
    name: 🏗️ Vite Build
    runs-on: ubuntu-latest
    needs: lint-and-test
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: "npm"
          cache-dependency-path: frontend/package-lock.json

      - name: Install & build
        run: |
          cd frontend
          npm ci
          npm run build
        env:
          VITE_API_BASE_URL: https://api.shopwave.app

      - name: Check bundle size
        run: |
          echo "📦 Build output size:"
          du -sh frontend/dist/
          echo "📄 JS chunks:"
          find frontend/dist/assets -name "*.js" -exec ls -lh {} \;
📦
Bundle Size Tracking: The workflow logs the total build output and individual JS chunk sizes. Consider adding a budget threshold (e.g., <300KB gzipped).

MCP Servers CI

.github/workflows/mcp-ci.yml — Matrix strategy for 6 servers

Matrix Build Strategy

Instead of 6 separate workflow files, a single matrix workflow tests all MCP servers in parallel. Each server gets its own isolated job but shares the same CI logic.

📄 .github/workflows/mcp-ci.yml 
# ──────────────────────────────────────────────────────────────
# ShopWave MCP Servers CI — Matrix build for all 6 servers
# ──────────────────────────────────────────────────────────────

name: MCP Servers CI

on:
  push:
    branches: [main]
    paths: ['mcp-servers/**']
  pull_request:
    branches: [main]
    paths: ['mcp-servers/**']

jobs:
  test-mcp-servers:
    name: 🔌 ${{ matrix.server }}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false  # Don't cancel other servers if one fails
      matrix:
        server:
          - inventory
          - payments
          - search
          - notifications
          - analytics
          - content

    services:
      postgres:
        image: postgres:18-alpine
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: mcp_test_db
        ports: ["5432:5432"]
        options: --health-cmd "pg_isready" --health-interval 10s

    steps:
      - uses: actions/checkout@v4

      - name: Set up Python 3.12
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: |
          cd mcp-servers/${{ matrix.server }}
          pip install -e ".[dev]"

      - name: Lint with Ruff
        run: |
          cd mcp-servers/${{ matrix.server }}
          ruff check .

      - name: Run tests
        run: |
          cd mcp-servers/${{ matrix.server }}
          pytest tests/ -v --tb=short
        env:
          DATABASE_URL: postgresql://test:test@localhost:5432/mcp_test_db
          MCP_INTERNAL_API_KEY: test-mcp-key
          RAZORPAY_KEY_ID: rzp_test_ci
          RAZORPAY_KEY_SECRET: test_secret_ci
          SENDGRID_API_KEY: SG.test_ci
          ANTHROPIC_API_KEY: sk-ant-test_ci

      - name: Build Docker image
        run: |
          docker build -t shopwave-mcp-${{ matrix.server }}:ci \
            ./mcp-servers/${{ matrix.server }}
⚠️
External API Keys in CI: Use dummy/test keys in CI. The mcp-search server needs pgvector extension installed — add CREATE EXTENSION IF NOT EXISTS vector; to a CI setup step.

Deployment Workflow

.github/workflows/deploy.yml — Production auto-deploy
📄 .github/workflows/deploy.yml 
# ──────────────────────────────────────────────────────────────
# ShopWave Production Deployment
# Runs ONLY on merge to main, after CI passes
# ──────────────────────────────────────────────────────────────

name: Deploy to Production

on:
  push:
    branches: [main]

concurrency:
  group: production-deploy
  cancel-in-progress: false  # Never cancel an in-progress deploy

jobs:
  # ── Database Migrations ─────────────────────────────
  migrate:
    name: 🗃️ Run Migrations
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install Alembic
        run: cd backend && pip install -e .

      - name: Run Alembic migrations on Neon
        run: cd backend && alembic upgrade head
        env:
          DATABASE_URL: ${{ secrets.NEON_DATABASE_URL }}
          SECRET_KEY: ${{ secrets.SECRET_KEY }}

  # ── Deploy Backend to Railway ────────────────────────
  deploy-backend:
    name: 🚂 Deploy Backend
    runs-on: ubuntu-latest
    needs: migrate
    steps:
      - uses: actions/checkout@v4

      - name: Install Railway CLI
        run: npm install -g @railway/cli

      - name: Deploy to Railway
        run: railway up --service backend --detach
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}

      - name: Wait for deploy & health check
        run: |
          sleep 30
          curl --fail --max-time 10 \
            ${{ secrets.BACKEND_URL }}/health \
            || exit 1
          echo "✅ Backend is healthy"

  # ── Deploy MCP Servers to Railway ─────────────────────
  deploy-mcp:
    name: 🔌 Deploy MCP Servers
    runs-on: ubuntu-latest
    needs: migrate
    strategy:
      matrix:
        server:
          - inventory
          - payments
          - search
          - notifications
          - analytics
          - content
    steps:
      - uses: actions/checkout@v4

      - name: Install Railway CLI
        run: npm install -g @railway/cli

      - name: Deploy ${{ matrix.server }}
        run: |
          railway up \
            --service mcp-${{ matrix.server }} \
            --detach
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}

  # ── Post-deploy Verification ─────────────────────────
  verify:
    name: ✅ Post-Deploy Smoke Tests
    runs-on: ubuntu-latest
    needs: [deploy-backend, deploy-mcp]
    steps:
      - name: Health check — Backend
        run: curl --fail ${{ secrets.BACKEND_URL }}/health

      - name: Health check — Frontend
        run: curl --fail ${{ secrets.FRONTEND_URL }}/health

      - name: Smoke test — Products API
        run: |
          response=$(curl -s -o /dev/null -w "%{http_code}" \
            ${{ secrets.BACKEND_URL }}/api/v1/products?limit=1)
          [ "$response" = "200" ] && echo "✅ Products API OK" || exit 1

      - name: Notify on success
        if: success()
        run: echo "🚀 All services deployed and verified!"

      - name: Notify on failure
        if: failure()
        run: echo "❌ Deployment verification failed — check logs"
🚨
Concurrency lock: The concurrency setting ensures only one deploy runs at a time. cancel-in-progress: false prevents abandoning a half-deployed state.

Branching Strategy

GitHub Flow — simple and effective

Recommended: GitHub Flow

For a project of ShopWave's scale, GitHub Flow strikes the right balance between simplicity and safety:

Branch Purpose Deploys To Protection
main Production-ready code 🚀 Production (auto) Branch protection, required CI, 1 review
feat/* New features 🔍 Preview (Vercel) None — developer branch
fix/* Bug fixes 🔍 Preview (Vercel) None — developer branch
hotfix/* Critical production fixes 🚀 Production (fast) Admin bypass + post-merge review
🔒
Branch Protection Rules for main: Require status checks to pass (Backend CI + Frontend CI + MCP CI), require at least 1 approving review, dismiss stale reviews, restrict force pushes.

Neon Database Branching

Neon's killer feature is database branching. Each PR can get its own database copy:

📄 PR Preview Database Workflow (excerpt) 
# In your PR workflow, add:

- name: Create Neon branch for PR
  uses: neondatabase/create-branch-action@v5
  id: neon-branch
  with:
    project_id: ${{ secrets.NEON_PROJECT_ID }}
    branch_name: pr-${{ github.event.number }}
    api_key: ${{ secrets.NEON_API_KEY }}

- name: Run tests against PR database
  run: cd backend && pytest
  env:
    DATABASE_URL: ${{ steps.neon-branch.outputs.db_url }}

Each PR tests against an isolated database branch — no interference between developers.

Post-Deploy Monitoring

Ensuring production stays healthy
1

Uptime Monitoring

  • Better Stack pings /health every 60s
  • Alerts via Slack, email, SMS on downtime
  • Public status page for customers
  • Monitor all 8 services independently
2

Error Tracking

  • Sentry SDK in FastAPI + React
  • Capture unhandled exceptions with stack traces
  • Release tracking tied to Git commits
  • Performance monitoring (slow queries, endpoints)
3

Log Aggregation

  • Structured JSON logs from all services
  • Better Stack Logs for centralized search
  • Filter by service, severity, request ID
  • Retained for 30 days minimum
4

Scheduled Health Check

  • GitHub Actions cron workflow every 5 min
  • Checks all endpoints + MCP servers
  • Opens GitHub Issue on repeated failure
  • Runs outside of deploy pipeline
📄 .github/workflows/health-check.yml 
# ──────────────────────────────────────────────────────────────
# Scheduled Health Check — runs every 5 minutes
# ──────────────────────────────────────────────────────────────

name: Health Check

on:
  schedule:
    - cron: "*/5 * * * *"
  workflow_dispatch:  # Manual trigger

jobs:
  check:
    name: 🏥 Health Check
    runs-on: ubuntu-latest
    steps:
      - name: Check Backend API
        run: curl --fail --max-time 10 ${{ secrets.BACKEND_URL }}/health

      - name: Check Frontend
        run: curl --fail --max-time 10 ${{ secrets.FRONTEND_URL }}/health

      - name: Check Products Endpoint
        run: |
          status=$(curl -s -o /dev/null -w "%{http_code}" \
            "${{ secrets.BACKEND_URL }}/api/v1/products?limit=1")
          [ "$status" = "200" ] || exit 1

      - name: Create issue on failure
        if: failure()
        uses: actions/github-script@v7
        with:
          script: |
            await github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: '🚨 Production health check failed',
              body: `Health check failed at ${new Date().toISOString()}.\n\nRun: ${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId}`,
              labels: ['bug', 'production', 'urgent']
            })
